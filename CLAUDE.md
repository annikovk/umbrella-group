# CLAUDE.md

Проект сайта **taxlab.ru** — WordPress-сайт бухгалтерских/юридических услуг.
Локально это две вещи одновременно: **полное зеркало** живого `httpdocs` и
**git-репозиторий своего кода** (`annikovk/umbrella-group`).

## Где что живёт

| | Где | Что |
|---|---|---|
| Живой сайт | `annikov.com:/var/www/vhosts/taxlab.ru/httpdocs` | источник истины, WordPress 6.5.10, PHP 8.3 |
| Зеркало | `httpdocs/` (2.4 ГБ, ~16 тыс. файлов) | побайтовая копия сервера, обновляется скриптом |
| Репозиторий | `annikovk/umbrella-group`, ветка `master` | только свой код, ~320 файлов |
| Стейджинг | `annikov.com:/var/www/vhosts/taxlab.ru/staging.taxlab.ru` | отдельный docroot со статикой, в зеркало не входит |

Сервер — Plesk. Ходим по `ssh annikov.com` (порт и юзер прописаны в
`~/.ssh/config`), файлы vhost'а читаются только через `sudo` — он passwordless.

БД: MySQL `wp_taxlab`, префикс таблиц `r17Y1_`. Пароль — в
`httpdocs/wp-config.php` (в git не едет).

## Обновить зеркало

```bash
tools/sync-from-server.sh
```

Односторонний rsync с `--delete`: сервер → локально. `.git` лежит выше
`httpdocs/`, так что удалением ему ничего не грозит. После синка `git status`
показывает, что изменилось на сайте с последнего коммита, — по нему и коммитим.

## Что попадает в git, а что нет

В репозитории — только код, который писали руками:

- `httpdocs/wp-content/themes/umbrella-group/` — своя тема, основной объём;
- `httpdocs/wp-content/themes/flatsome/inc/shortcodes/{accordion,team_members}.php`
  — два правленых шорткода вендорской темы, остальной flatsome не трогаем;
- `httpdocs/{robots.txt,sitemap.xml,googlefe7ca66817e2398c.html}`;
- `httpdocs/wp-content/{index,advanced-cache,maintenance}.php`;
- семь картинок из `uploads`, залитых руками под тему.

Всё прочее отрезано в `.gitignore` и живёт только в зеркале:

- ядро WordPress, плагины (93 МБ), медиатека (1.4 ГБ), кэш;
- `wp-config.php` — там пароль БД и соли;
- `protect918/` (653 МБ) и `F_F/` — защитный скрипт и adminer, в публичный репо
  им нельзя;
- `wp-content/themes/umbrella-group/assets/Umbrella_2_1.mp4` — 149 МБ, выше
  жёсткого лимита GitHub в 100 МБ. Файл есть в зеркале и на сервере, в репо его
  нет и быть не может; если понадобится версионировать — только через Git LFS.

**Репозиторий публичный.** Прежде чем расширять скоуп, проверяй, что в новых
файлах нет ключей, паролей и персональных данных.

## Деплой

Автодеплоя нет: на сервере нет `.git`, и ничто не тянет GitHub. Репозиторий —
слепок кода, а не источник для сайта. Правки уезжают на сервер вручную (Plesk /
IDE upload), после чего `tools/sync-from-server.sh` + коммит возвращают их сюда.
Порядок «сначала git, потом сервер» здесь не работает — не притворяйся, что
работает.

## Гочи

- **macOS openrsync.** Системный `rsync` — это openrsync (протокол 29), он не
  знает `--info=progress2` и молча падает в usage. Флаги в скрипте подобраны под
  него; не подставляй флаги из GNU rsync 3.x, не проверив.
- **Коллизии по регистру.** В `uploads` четыре файла отличаются от соседей только
  регистром первой буквы (`На-сайт.png` / `на-сайт.png` и т.п.) и различаются
  содержимым. APFS регистронезависим, поэтому в зеркале из каждой пары один файл;
  вторые копии лежат в `_case-conflicts/` (см. README там). Зеркало = 15989
  файлов против 15993 на сервере ровно по этой причине, а не из-за сбоя закачки.
- **`DISALLOW_FILE_MODS` и `DISALLOW_FILE_EDIT` включены** — правка плагинов и тем
  из wp-admin запрещена, только через файлы.
- **WP Rocket + Redis-кэш.** После правки темы на сервере кэш надо сбрасывать,
  иначе изменения не видны.
- **`.htaccess` блокирует три IP** (`87.117.60.143`, `87.117.58.42`,
  `188.187.181.218`) и в git не отслеживается.
- В корне сайта валяются `index_2.php` (дебажный дубль индекса с проверкой на
  конкретный IP) и `phpinfo.php` — оба живые и отдаются наружу.
